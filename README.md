# SkillBridge AI

An AI-powered career platform: admin-approved accounts, AI skill assessment, skill-gap analysis,
jobs & internships, local job radar, AI resume studio, AI career coach and AI assistant.

Everything is dynamic and database-backed. **There are no hard-coded questions, jobs, or API keys** –
assessment questions, role requirements, job recommendations, resume edits and coaching are generated by
an AI provider from the user's real data; all state is stored in SQLite.

## Quick start

Requires **Node.js 20.16+** (22 recommended – uses the built-in `node:sqlite`).

```bash
npm install
cp .env.example .env      # then edit .env (see below)
npm start                 # http://localhost:3000
```

### Configure `.env`

| Variable | Purpose |
|---|---|
| `AI_PROVIDER` | `gemini` (free key at aistudio.google.com/apikey), `openai` (or any OpenAI-compatible API via `AI_BASE_URL`) or `anthropic` |
| `AI_API_KEY` | your key – **server side only, never sent to the browser** |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | admin account created on first start. If the password is empty a random one is printed **once** in the console |
| `COOKIE_SECURE` | set `true` when served over HTTPS |

**Forgot the admin password?** The admin account is created only once (on first start), so changing `ADMIN_PASSWORD` in `.env` later has no effect. Run `npm run reset-admin -- admin@example.com NewPass123`, restart, and sign in through **Admin login** (not the normal Sign in).

The app starts without a key; AI features then show a clear "not configured" message.

## How it works

1. **Register → admin approval.** New users are `pending` and cannot sign in until an admin approves them
   (Admin login → *Registrations*). Rejected users are blocked and their sessions revoked.
2. **Admin dashboard:** approve / reject / delete users, manage the skills catalog offered in assessments, send announcements (delivered as notifications).
3. **User dashboard (5 features + notification bell):** AI Skill Assessment · Skill Gap Analysis · Jobs & Internships · AI Resume Studio · AI Career Coach.

Design notes
- Assessment: choose up to 5 skills → AI writes 10 fresh questions (MCQ + short answer, mixed difficulty). The answer key stays on the server; scoring per skill is computed deterministically; short answers are graded by the AI against a rubric.
- Skill gap: required levels come from the AI (cached), current levels from *your* stored assessments. Unassessed skills are shown as "not assessed", never guessed.
- Jobs & Internships: the AI suggests suitable job and internship roles from your real data; each role links to searches on LinkedIn, Indeed, Naukri/Internshala and Google Jobs (plain links – no jobs API or key needed).
- Resume Studio: PDF/DOCX/TXT upload → structured extraction → truthful polish. A guardrail removes any skill, certification, employer or number the AI adds that is not in the original text. DOCX export.
- Security: scrypt password hashing, HttpOnly SameSite session cookies, origin checks, rate limits, CSP, no inline scripts, per-user data isolation, secrets only in environment variables.

## Sharing the project with a friend / moving to another PC

The database (`data/skillbridge.db`) and your `.env` live **on your own computer** – users, assessments and
resumes you created are *not* part of the code. To share the project:

1. **Stop the server** (Ctrl + C) and zip the folder **without** `node_modules`, `.env` and `data/*.db*`.
   (`node_modules` contains files built for your operating system, and `.env` contains your secret AI key.)
2. Your friend needs **Node.js 22.13 or newer** (`node -v`), then runs:
   ```bash
   npm install
   cp .env.example .env     # Windows: copy .env.example .env  → then add AI_API_KEY
   npm start
   ```
3. On every start the admin login is synced from `.env` (`ADMIN_EMAIL` / `ADMIN_PASSWORD`), so the admin can always sign in with the values in her own `.env` (default `admin@example.com` / `Admin@12345`).
4. She starts with an empty database. `npm run seed` adds an approved demo user (`demo@example.com` / `Demo@12345`); otherwise register a user and approve it from the admin dashboard.

To move the actual data too, stop the server first, then copy the `data/` folder (it is a single portable file after a clean stop).

## Tests

```bash
npm test          # end-to-end API checks (spawns the server against a local mock of the AI service)
npm run test:ui   # optional browser smoke test (requires: npm i -D playwright && npx playwright install chromium)
```

The mock upstream (`tests/mock-upstream.js`) is used **only by tests**; the running app never uses mock data.

## Project layout

```
server.js            entry point
server/              config, db (SQLite), auth, ai client, resume parse/export, routes/
public/              single-page frontend (index.html, css/app.css, js/*.js)
tests/               e2e + UI smoke tests, fixtures
data/                SQLite database (created at runtime)
```

## Deploying

Any Node host works (Render, Railway, a VPS). Set the environment variables, keep `data/` on a persistent
disk, serve over HTTPS and set `COOKIE_SECURE=true`.
